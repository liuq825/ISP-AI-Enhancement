# 中文代码注释规范

## 目标

仓库中的代码需要让接手者能够理解“为什么这样设计、输入输出契约是什么、哪里不能随意
修改”，而不只是把语句逐行翻译成中文。注释属于工程交付的一部分，与测试和配置同步维护。

## Python

- 每个模块必须有中文模块说明，交代职责、边界和关键约束。
- 每个类、函数和方法必须有中文 docstring，至少说明用途；涉及张量时应写明关键 shape、
  通道语义或数值范围。
- 对输入 ABI、SimpleGate 成对通道、数据防泄漏、量化边界等不直观逻辑添加行内注释。
- 不写“创建变量”“进入循环”一类复述语法的低信息注释。
- 行为改变时同步修改注释；过期注释按缺陷处理。

`tests/test_chinese_documentation.py` 会扫描 `src/` 和 `tests/`：模块、类、同步/异步函数
缺少包含中文的 docstring 时，CI 直接失败。该检查保证覆盖面，代码评审负责判断说明质量。

## C++ 与 PowerShell

- C++ 公共接口使用中文 Doxygen 注释，说明所有权、生命周期、单位、失败语义和回退要求。
- PowerShell 脚本使用 comment-based help 说明用途；原生进程退出码、路径解析和版本记录等
  易错点必须写行内注释。
- 转换器参数示例必须注明适用的 DDK/产品版本，不能暗示不同工具链参数可以通用。

## 配置

每个 YAML 文件开头说明用途。影响模型 ABI、数据许可、量化精度、分块接缝或部署结果的字段
需要中文注释；纯粹显而易见的重复字段不要求逐行注释。

## 本地检查

```powershell
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\python.exe -m pytest tests/test_chinese_documentation.py
```
